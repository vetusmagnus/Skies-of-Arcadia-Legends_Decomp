# Contributing to the Skies of Arcadia Legends decomp

Matching decomp of the GameCube game (GEAE8P, USA Rev 0). It's built on encounter's dtk-template.

## Build
- `python configure.py && ninja`. The build must end with `build/GEAE8P/main.dol: OK`. Never commit a change that breaks the match.
- Game code (`src/game/`, `include/game/`, `include/ninja.h`) must be plain C that compiles to the original bytes: no inline asm, `#pragma`, asm includes or fakematch markers. `tools/check_game_src.py` runs before anything compiles and stops the build on a hit. Library code under `extern/` is exempt (its asm functions are asm in the original libraries).
- The disc image in `orig/GEAE8P/` is a symlink to the user's RVZ. Never commit game data: no disc images, DOLs, extracted files, or `build/`.

## Conventions
- Game code: MWCC **GC/1.3.2** with `cflags_game` (adds `-use_lmw_stmw on` and `-inline noauto`). Use the `GameLib` helper in `configure.py`; sources go in `src/game/`, headers in `include/game/` (Ninja prototypes in `include/ninja.h`). See `docs/compiler.md`.
- A repeated block inside several game functions is an `inline` function (auto-inlining is off). Uninitialized globals: declare them `extern` in the header and define them after the last function, in reverse order, to get the original `.bss` layout (`docs/compiler.md`).
- File names under `src/game/` are ours (the originals aren't known); file boundaries come from the data layout: a file's `.sdata2` starts 8-aligned, and its `.data` strings come before its jump tables.
- Library code: borrowed under `extern/` (SDK/MSL/TRK from tw2004, MusyX from AxioDL/musyx). The `configure.py` block between the `library import` markers and `config/GEAE8P/lib_import.json` are generated by `tools/import_libs.py`. Re-run the script rather than editing them by hand.
- Any edit to a file under `extern/` goes in the "Local modifications" list in `extern/README.md`.
- Skies-specific build choices for borrowed code live in `tools/import_libs.py`: `FLAG_SUBST` (e.g. `CARD_PATCH_2003=0`), `ALTERNATES` (a copy from another vendored tree) and `LOCAL_LIBS` (libraries vendored here directly, with their flags, such as MusyX). Re-running the import needs a tw2004 checkout at the pinned commit (see `docs/sdk_import.md`); it isn't kept in the repo.
- dtk's signature names can be wrong when two functions compile to the same bytes (it named `CARDRead` as `CARDWrite`). Fix `symbols.txt` when the call graph disagrees.
- Functions named from behavior rather than matched source (the Ninja library, the SDK `PSMTX*`/`PSVEC*` routines it calls) go in `symbols.txt` with their evidence in `docs/ninja.md`. Only name what the code clearly shows; mark inferred Ninja names as "likely" there.
- To place newly matched source: compile it, run `tools/tusplit.py <obj>` for the `splits.txt` entry, then `tools/fixsplits.py`.
- Matching workflow and what MWCC cares about: `docs/matching.md`; tools in `tools/match/` (run `tools/match/asmindex.py build` after `ninja` regenerates the asm). Open near-misses: `docs/ui.md` Open.

## Keeping docs current
- After a change that affects progress, run `python tools/update_status.py`. It regenerates the README Status block. Other docs link to that block instead of repeating numbers, so don't add counts elsewhere.
- Update `docs/compiler.md` (compiler and flag evidence) and `docs/sdk_import.md` (library region, rejected files) when their findings change.

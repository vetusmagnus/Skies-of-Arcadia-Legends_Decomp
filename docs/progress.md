### Linking tasks.c and sound.c (2026-10-26)

sound.c now links and `main.dol` is byte-identical. tasks.c does not, but its blockers are four
functions, not data. What we learned (it applies to every unit with strings or local array
initialisers):

- **The original built these files with `-inline deferred`.** Deferred codegen emits functions in
  *reverse* source order, creates local array initialisers (B702VoiceNo's table, fn_8003DBAC's
  `"ABG"`) at parse time so they land ahead of every string literal, and writes the strings and
  float constants in codegen order. The `.rodata`/`.sdata2` order in the DOL is exactly that: table
  first, then the strings in address order. The matching source therefore lists the functions from
  the highest address down, with the inline helpers and prototypes first (they must precede their
  users). Per-file flags in `configure.py`: `extra_cflags=["-str reuse,readonly", "-inline
  noauto,deferred"]`. `-str reuse,readonly` puts strings in `.rodata`/`.sdata2` instead of `.data`.
  Evidence on a 3-function test file is in docs/compiler.md. Other units with string-offset-only
  near misses (battle.c's fn_800308FC, effect.c, anything that shows `lbl_xxxx+0x78` string offsets)
  probably want the same treatment.
- **tasks.c was two files.** The 4-byte zero gap at 0x802DD234 is alignment: `chunklist.c` (code
  0x80035918-0x80036520, its only data the jump table at 0x802DD0C8) ends there and `tasks.c`
  starts with the 8-aligned task table `lbl_802DD238`. The boundary is only known to lie between
  fn_8003617C and fn_800367E8 (the first user of `lbl_802DD238`); we put it at fn_80036520.
- Data comes from C now: sound.c defines `CharSeTable` (the voice id tables), the task tables
  `lbl_802DD238`/`lbl_802DE208` are in tasks.c, the strings are the compiler's. tasks.c's compiled
  `.rodata`, `.data` and `.sdata2` equal the original bytes (checked with relocations masked).
- Why tasks.c can't link partly: `"ABG"` is the first `.sdata2` entry of the unit that contains
  fn_8003DBAC, ahead of the floats used by earlier functions, so fn_8003DBAC can't be split off
  into its own unit; the whole of tasks.c waits for fn_8003DBAC and fn_8003DCF4. chunklist.c waits
  for fn_80035918 and fn_80035C38; its two matching stretches (0x8003598C-0x80035C38 and
  0x80035D4C-0x80036520) could be split into units of their own if linking them early is worth it.
- Near misses, for whoever takes them: fn_80035918 (the original has an extra `b`, and the
  parameter `mr` sits after the loop; ~25 loop/inline shapes tried, all give the same 26
  instructions), fn_80035C38 (two locals swap r29/r31; all 5040 declaration orders tried),
  fn_8003DBAC (the `rem` of `% 1000` is `extsh` into r3 then `mr r6,r3`; ~100 orderings and
  type variants tried), fn_8003DCF4 (the third TargetMatch compares `obj->type` first: swapping the
  arguments gets the compare right but moves the registers).

Agent batches

The functions above outside drawstate/uiobj/text came from parallel agent batches: batch 1 (16 agents on
137 functions, 126 matched after Opus retries and merging), batch 2 (16 agents on 177 functions, 103
matched; Sonnet only) and batch 3 (16 agents on 86 functions, 62 matched: 1 Haiku agent on the 21

Agent contexts stayed at 105-230k tokens. Merging into an existing file is the costly part: every new
function brings its own `extern` types, and they conflict (one `lbl_` global declared with several struct
types). The merge agents unified them into one declaration per global; `build/agents/merge.py` only
renames clashing typedefs.

**Model rule (from 2026-10-26, for usage):** no Opus agents or Opus retries. Haiku (`model: "haiku"`) for
functions under 200 bytes, Sonnet (`model: "sonnet"`) for everything else, merging included; set the model
explicitly on every Agent call. Cap each function at ~10 variants and log the rest as near misses. In batch 1
most of the cost was five Opus retry agents and the Opus merges; agent contexts peaked at 90-230k tokens.

### Opus near-miss batch (2026-10-26)

Start-over pass on the logged near misses, smallest first (16 to 132 bytes), 16 Opus 5.5 agents (set explicitly) with
about 10 tries per function, no retry or merge agents: 14 agents on 8 functions each (112 functions), one on the
model.c/chunk.c/btlchar.c blockers, one on the tasks.c/chunklist.c blockers. 119 attempted, 92 more functions match
(3,402 to 3,494, including a few siblings the agents solved on the way); every one re-checked with fdiff and
`floatcheck.py`, merged by `merge6.py` in the coordinating session, `main.dol` still rebuilds byte-identical.
The causes were mostly small and reusable:

- A comparison result held in a named `int` and returned through `!x` (or `if (..) return 1; return 0;`) gives the
  `xor/srawi/subf/srwi` forms that plain `return a == b` folds away; `return n <= c` also schedules differently from
  the if/return form.
- An extern array's declared size picks the addressing: 8 bytes or less is `sda21`, larger is `lis/addi`
  (`lbl_8034718C[2]`, `lbl_80346C44` as an 8-byte struct, `lbl_80347148[4]`).
- Return type decides where `extsb` lands and whether r3 stays live (`int f(void)` vs `s8`, a callback with no
  `return` at all); a callee's real parameter type (`s32` vs `s16`) fixes load order.
- A counted loop that MWCC unrolls keeps a leading `cmpwi/bge` guard: write the loop, not the unrolled stores.
  `do { } while (i < n)` gives the `cmpwi/blt` shape instead of `mtctr`.
- Struct-typed table access (`tbl->row[i].f`, a `Mem *m` local, a typed `work` pointer) fixes folded index math that
  casts and flat byte offsets cannot.
- Evaluating `lbl = fn_x(..)` chains, a held local for every field read first, and the original's argument order for
  mixed int/float prototypes (fn_801D5DD8) fix scheduling.

`floatcheck.py` caught real bugs fdiff cannot see: fn_801E4FD4 and fn_801E74D0 (model.c) used the wrong constants,
and fn_800304DC (battle.c) passed `0.0f` where the original passes `30.0f`; all fixed.

What fixed the near misses (new, on top of the list in the earlier section):

- A `static inline` helper for a repeated block or a bool test (`FlagTest`, `MapInRange`, `Cat`, `RandomLivingAlly`,
  `FreeIf`, `Close`, `Relocate`/`ClearWork`) fixes doubled `beq`s, `neg/or/srwi` flag idioms and loop-counter versus
  offset register swaps; the explicit `!= 0` on the inline's boolean result is what makes the `neg/or/srwi` form.
- Declaring a `.rodata` table `const` lets MWCC hoist its loads above stores (`lbl_802B8F20`, `lbl_802B8EDC`).
- `extern` array sizes decide `sda21` versus `lis/addi` (sized to 8 bytes or less, or declared at full size).
- An empty `case 0xfe: break;` / `case 3: break;` / `case 0:` in front of `default:` reproduces the original's compare
  tree; a dead second `beq` comes from `if (p) { if (p) f(p); p = 0; }`.
- A chained store (`a = b = c = 0.0f`) and `x / 2.0f` versus `x * 0.5f` fix float scheduling and fcmp/fmul operand order.
- `int` versus `s32` (`long`) parameters change the code at calls and inline arguments; try `int` when a stray `mr` appears.
- Struct-typed tables and a held local for each field read (`Party`, `Rec5`, `Joint`) beat casts and flat offsets.
- Comparison held in a named `int` (`s32 set = ... != 0`), or `if (c) return 1; return 0;`, gives the xor/srawi forms.

What worked:

- Batch 1 used Opus for a second pass on the near misses, starting from the first pass's file. The
  fixes it found are worth trying first: inline helpers for a repeated
  block, pointer-walked destination arrays (`pv++` as the loop's last statement), a `switch` with
  `default:` first to stop constants being hoisted, and narrow return types (`s8`/`s16`) fixed most
  register and scheduling diffs.
- Merging is also a job for agents (one per file, Sonnet for small files), but re-run fdiff over every
  function of the merged file yourself, with no agent running (parallel runs of the tools can
  report false diffs), and reject tricks that only exist for the bytes: padding arrays sized for
  the frame, type-changing copies of a parameter.
- One agent per batch of ~10-20 functions that are contiguous or siblings. Sonnet matched almost
  everything under 400 bytes, including every member of the task-handler family; Opus took the
  larger ones. The near misses were register allocation and block layout, not size, so batches of
  handler-style code up to ~0x300 bytes can go to Sonnet too.
- Each agent works only in `build/agents/<id>/`, one self-contained `fn_<addr>.c` per function, and
  verifies with `tools/match/fdiff.py`. All scratch stays in the repo's gitignored `build/`: the
  tools in `tools/match/` already write their per-attempt files to `build/match/` and delete them,
  and an agent's own scripts write candidates into its folder and delete each one after scoring.
  No `tempfile.mkdtemp()` or other writes to `%TEMP%`: 16 agents scoring thousands of variants each
  leave hundreds of thousands of folders there that nothing cleans up. Nothing touches `src/`, git or the build until a person
  (or the coordinating session) re-verifies every claimed match and integrates.
- Integration is its own step: merge a file's functions into one translation unit with shared
  types, then re-run fdiff over every function. Shared `static inline` helpers matter: the task
  allocation (`TaskAlloc`/`TaskNew`, the "Error: tasSetTask" checks) is inlined into 84 handlers,
  and several functions only match once their helper is defined once, before its users.
- Families pay off: matching one member and adapting it gave 86 handlers. Look for runs of
  functions with the same call pattern (`tools/match/asmindex.py`).
